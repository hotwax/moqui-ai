## Problem Statement

The moqui-ai component needs a pluggable embedding API for RAG (Retrieval Augmented
Generation) — specifically for the JVector integration that will let agents search
product catalog, order history, and knowledge content by semantic similarity.

The existing `LlmProvider` pattern (interface + abstract HTTP base + per-provider
adapters + registry in AiToolFactory) works cleanly. The embedding API follows the
same pattern so the codebase stays consistent.

Decided: OpenAI `text-embedding-3-small` for v1. Embedding config is independent of
LLM config — a deployment can use different vendors for each. Embedding API key and
base URL have their own properties (`ai_embedding_api_key`, `ai_embedding_base_url`).

## What Makes This Work

The LlmProvider pattern is already proven. This is a straight application of it:
- `chat(Map)` becomes `embed(Map)`
- `encodeRequest`/`decodeResponse` do the wire-format translation
- Same `RestClient` transport, same System prop config, same mock queue for tests
- No new framework concepts, no new dependencies

The OpenAI embeddings API format is the de facto standard — most modern providers
speak it natively. One implementation (`EmbeddingProvider`) covers OpenAI, Azure
OpenAI, Voyage AI, Mistral, and others by changing only the base URL and model name.
Providers that don't speak the format (Cohere) are out of scope for v1.

The `inputType: document|query` hint is in the contract even though the v1 default
provider ignores it. Providers that distinguish document from query vectors (Voyage,
Cohere) can use it without a breaking interface change.

## Naming

| Name | Role |
|---|---|
| `Embedder` | Interface — the contract every implementation must satisfy |
| `EmbeddingProvider` | The real implementation — speaks the OpenAI-compatible wire format |
| `MockEmbeddingProvider` | Test implementation — scriptable, no HTTP |

`Embedder` follows the Java single-responsibility naming convention (`Runnable`,
`Callable`). `EmbeddingProvider` is the concrete class — no vendor name, because
it works with any provider that speaks the format.

## Premises

1. `Embedder` (interface) follows the Map-in/Map-out + AbstractBase + adapters
   pattern exactly as `LlmProvider` does.

2. The embedder registry lives in `AiToolFactory` alongside LLM providers. Embedding
   config is independent: `ai_embedding_api_key` and `ai_embedding_base_url` are
   separate from `ai_openai_key` and `ai_openai_base_url`. The factory falls back to
   `ai_openai_key` if `ai_embedding_api_key` is not set, so existing single-vendor
   deployments require no config change.

3. The `embed()` contract includes `inputType: "document"|"query"` even though v1's
   `EmbeddingProvider` ignores it. Future adapters can use it without a breaking change.

4. Azure OpenAI, Voyage AI, Mistral are NOT separate classes. They are `EmbeddingProvider`
   with a different `ai_embedding_base_url` and `ai_embedding_model`. Same code,
   different config.

5. v1 ships: `EmbeddingProvider` + `MockEmbeddingProvider`.

## Approaches Considered

### Approach A: One OpenAI-compatible implementation + Mock (CHOSEN)
`Embedder` interface + abstract base + one real implementation + mock. Registers in
AiToolFactory. MoquiConf adds four props. One implementation covers all providers
that speak the standard format. Effort: half day, 5 files.

### Approach B: Per-vendor adapters
A + `CohereEmbeddingProvider` + `OllamaEmbeddingProvider`. Cohere has a different
wire format; Ollama is single-text, no auth, local HTTP. Effort: 2 days, 9 files.
Rejected: Cohere can be fronted by a LiteLLM proxy if needed, keeping moqui-ai clean.

### Approach C: Service-layer switch (rejected)
No Groovy interface. `generate#Embeddings` service has if/else per provider.
Breaks the established `LlmProvider` pattern, untestable without refactoring.

## Recommended Approach

**Approach A.** One implementation covers the majority of hosted embedding services
via URL config. Cohere and Ollama are deferred — if needed, run LiteLLM as a proxy
to expose them behind the standard format rather than adding adapters.

## Normalized API Contract

### Embedder interface

```groovy
interface Embedder {
    /** Registry key. "default" for EmbeddingProvider, "mock" for MockEmbeddingProvider. */
    String getName()

    /** request Map in → response Map out.
     *
     *  Request keys:
     *    texts       List<String>  required — one or more texts; must be non-empty
     *    inputType   String        optional — "document" (default) or "query"
     *                              implementations that don't distinguish ignore it silently
     *    model       String        optional — overrides the provider default
     *
     *  Response keys:
     *    embeddings  List<List<Float>>  one List<Float> per input text, same order
     *    model       String             actual model used (for audit)
     *    tokensUsed  int                total tokens consumed
     */
    Map embed(Map request)
}
```

### AbstractEmbeddingProvider (HTTP template, same shape as AbstractLlmProvider)

One deliberate deviation from `AbstractLlmProvider`: the constructor takes a `defaultModel`
parameter. LLM providers don't own a model default — it always arrives in the request.
Embedding providers need a default because callers don't always specify a model; it is a
deployment-level choice (`ai_embedding_model`). The `defaultModel` is captured at factory
init time; **changing `ai_embedding_model` at runtime requires a restart**.

```groovy
abstract class AbstractEmbeddingProvider implements Embedder {
    protected final String apiKey
    protected final String baseUrl
    protected final String defaultModel   // captured at init; restart required to change
    protected final int timeoutSeconds

    AbstractEmbeddingProvider(String apiKey, String baseUrl, String defaultModel, int timeoutSeconds)

    protected abstract String endpointPath()
    protected abstract Map<String, String> authHeaders()
    abstract String encodeRequest(Map request)
    abstract Map decodeResponse(String responseText)

    @Override
    Map embed(Map request) {
        String body = encodeRequest(request)
        RestClient rc = new RestClient().uri(baseUrl + endpointPath())
            .method('POST').contentType("application/json").timeout(timeoutSeconds).text(body)
        authHeaders().each { k, v -> rc.addHeader(k, v) }
        def resp
        try {
            resp = rc.call()
        } catch (Exception e) {
            throw new RuntimeException("Embedder ${name} HTTP error: ${e.message}", e)
        }
        int sc = resp.getStatusCode()
        String text = resp.text()
        if (sc < 200 || sc >= 300)
            throw new RuntimeException("Embedder ${name} HTTP ${sc}: ${text}")
        return decodeResponse(text)
    }
}
```

### EmbeddingProvider (OpenAI-compatible implementation)

Speaks the `/v1/embeddings` wire format. Works with any provider that exposes this
format: OpenAI, Azure OpenAI, Voyage AI, Mistral, Together AI, Fireworks AI.
Switching providers requires only `ai_embedding_base_url` and `ai_embedding_model`
config changes — no code changes.

```groovy
class EmbeddingProvider extends AbstractEmbeddingProvider {
    EmbeddingProvider(String apiKey, String baseUrl, String defaultModel, int timeoutSeconds)

    @Override String getName() { "default" }
    @Override protected String endpointPath() { "/embeddings" }
    @Override protected Map<String, String> authHeaders() {
        ["Authorization": "Bearer ${apiKey}"]
    }

    @Override String encodeRequest(Map request) {
        // inputType is accepted but not forwarded — the standard format has no input_type field.
        List<String> texts = request.texts as List<String>
        String model = (request.model ?: defaultModel) as String
        JsonOutput.toJson([model: model, input: texts])
    }

    @Override Map decodeResponse(String responseText) {
        Map json = new JsonSlurper().parseText(responseText) as Map
        Map usage = (json.usage ?: [:]) as Map
        List<List<Float>> embeddings = ((json.data ?: []) as List<Map>)
            .sort { it.index as int }
            .collect { it.embedding as List<Float> }
        String model = json.model as String
        return [embeddings: embeddings, model: model, tokensUsed: (usage.total_tokens ?: 0) as int]
    }
}
```

### MockEmbeddingProvider (same scriptable queue pattern as MockProvider)

Default response is a zero-vector of **1536 dims** (matches `text-embedding-3-small`).
Tests that use a different dimension model must enqueue an explicit response via
`MockEmbeddingProvider.enqueue(...)`. `reset()` clears both the script queue and
`LAST_REQUEST` so consecutive tests that check `LAST_REQUEST` don't see stale data.

```groovy
class MockEmbeddingProvider implements Embedder {
    private static final ConcurrentLinkedQueue<Map> SCRIPT = new ConcurrentLinkedQueue<>()
    static volatile Map LAST_REQUEST = null

    static void enqueue(Map r) { SCRIPT.add(r) }
    static void reset() { SCRIPT.clear(); LAST_REQUEST = null }

    @Override String getName() { "mock" }

    @Override Map embed(Map request) {
        LAST_REQUEST = request
        Map r = SCRIPT.poll()
        if (r != null) return r
        // Default: one zero-vector per input text (1536 dims = text-embedding-3-small).
        // Tests using a different model dimension must enqueue an explicit response.
        int dims = 1536
        List<List<Float>> embeddings = (request.texts as List<String>).collect {
            (0..<dims).collect { 0.0f }
        }
        return [embeddings: embeddings, model: "mock", tokensUsed: 0]
    }
}
```

## AiToolFactory Changes

Add an `embedders` registry alongside the existing `providers` LLM registry:

```groovy
// in AiToolFactory.groovy — additions only

private final Map<String, Embedder> embedders = [:]

// in init():
registerEmbedder(new MockEmbeddingProvider())
try {
    // ai_embedding_api_key is independent of ai_openai_key — different vendors may be
    // used for LLM and embeddings. Falls back to ai_openai_key so existing single-vendor
    // deployments require no config change.
    String embeddingKey = prop("ai_embedding_api_key") ?: prop("ai_openai_key")
    if (embeddingKey) {
        registerEmbedder(new org.moqui.ai.provider.EmbeddingProvider(
            embeddingKey,
            prop("ai_embedding_base_url") ?: "https://api.openai.com/v1",
            prop("ai_embedding_model") ?: "text-embedding-3-small",
            (prop("ai_timeout_seconds") ?: "60") as int))
        logger.info("AI: registered embedding provider (${prop('ai_embedding_base_url') ?: 'openai'})")
    }
} catch (Throwable t) { logger.warn("AI: skipped embedding provider init: ${t.message}") }

// New methods:
void registerEmbedder(Embedder e) { embedders.put(e.name, e) }

Embedder getEmbedder(String name) {
    Embedder e = embedders.get(name)
    if (e == null) throw new IllegalArgumentException("No embedder registered: ${name}")
    return e
}

Embedder getDefaultEmbedder() {
    // MoquiConf declares ai_embedding_provider="default" as the default-property.
    // The ?: "default" fallback fires only if the property is blanked at OS level.
    String name = prop("ai_embedding_provider") ?: "default"
    return getEmbedder(name)
}
```

Add four new `<default-property>` entries:

```xml

     ai_openai_key at runtime if not set, so single-vendor deployments need no change. -->
<default-property name="ai_embedding_provider" value="default"/>
<default-property name="ai_embedding_base_url" value="https://api.openai.com/v1"/>
<default-property name="ai_embedding_api_key"  value="" is-secret="true"/>
```

## generate#Embeddings Service

Thin wrapper. Logic lives in the Groovy provider, not the service.

```xml
<service verb="generate" noun="Embeddings" authenticate="true">
    <description>Generate embedding vectors for one or more texts using the configured
    embedder. inputType "document" is for ingest, "query" is for search — providers
    that distinguish the two use it; those that don't ignore it silently.</description>
    <in-parameters>
        <!-- texts must be non-empty; returns a validation error if the list is empty -->
        <parameter name="texts" type="List" required="true"/>
        <parameter name="inputType" default-value="document"/>
        <parameter name="model"/>         <!-- optional model override; omit to use provider default -->
        <parameter name="embedderName"/>  <!-- optional override; uses ai_embedding_provider default -->
    </in-parameters>
    <out-parameters>
        <parameter name="embeddings" type="List"/>  <!-- List<List<Float>> -->
        <parameter name="model"/>
        <parameter name="tokensUsed" type="Integer"/>
    </out-parameters>
    <actions>
        <script><![CDATA[
            if (!texts) { ec.message.addValidationError(null, "texts", "generate#Embeddings", "texts must be non-empty", null); return }
            def aiFactory = ec.factory.getTool("AI", org.moqui.ai.AiToolFactory.class)
            def embedder = embedderName
                ? aiFactory.getEmbedder(embedderName)
                : aiFactory.getDefaultEmbedder()
            Map embedReq = [texts: texts, inputType: inputType]
            if (model) embedReq.model = model
            def result = embedder.embed(embedReq)
            embeddings = result.embeddings
            model = result.model
            tokensUsed = result.tokensUsed
        ]]></script>
    </actions>
</service>
```

## Open Questions

1. **Cost tracking**: should `tokensUsed` from embedding calls flow into the existing
   `AiCostEntry` entity? Embedding cost is negligible today ($0.02/million tokens) but
   the infrastructure would be consistent. Defer or include in v1?

2. **Dimensions**: should the `Embedder` interface expose `dims` in the response? Useful
   when the JVector index is being initialized. Or should the VectorFacadeImpl be
   configured with a hardcoded dimension matching the chosen model?

3. ~~**Single text vs batch**~~ — **resolved**: v1 uses one `embed()` call per document in
   `index#VectorDocuments`. Batching is a follow-on optimization; measurable only at
   catalog sizes of 50k+ documents. Do not batch in v1.

## Success Criteria

- `EmbedderTests.groovy` passes with `MockEmbeddingProvider` (no API calls needed)
- `generate#Embeddings` service returns a `List<List<Float>>` of correct length for each input text
- `ec.factory.getTool("AI", AiToolFactory.class).getDefaultEmbedder()` returns
  `EmbeddingProvider` when a key is configured, `MockEmbeddingProvider` otherwise
- Switching to Voyage AI requires only `ai_embedding_base_url`, `ai_embedding_api_key`,
  and `ai_embedding_model` config changes — no code change
